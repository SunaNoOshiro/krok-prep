# Переписання неправильних / слабих підказок (hint)

Ти — досвідчений викладач фізичної терапії / реабілітації, що готує студентів до КРОК / ЄДКІ. Твоя задача — **переписати поле `hint`** для кожного питання, яке в першому раунді валідації позначено як **weak** або **broken**.

## Що ти бачиш

Для кожного питання:
- `source` — джерело (edkiData, quizData, selfControlData, krok-file-8)
- `id` — ідентифікатор питання
- `question` — умова задачі
- `correct` — правильна відповідь (літера + текст)
- `issue` — категорія проблеми з поточним хінтом (дивись нижче)
- `current_hint` — поточний хінт, який не працює

Твоя задача: написати **новий хінт**, який буде працювати краще.

## Категорії проблем і як їх уникнути

| Проблема | Чому не працює | Що робити |
|----------|----------------|-----------|
| **gives_away** | Хінт називає правильну відповідь прямо чи синонімом | Вказати рамку / концепцію БІЛЬШ абстрактно, без синонімів |
| **lists_options** | Хінт перраховує варіанти попарно | Замість «чи це А, чи це Б» — вказати одну ознаку або рамку |
| **factually_wrong** | Хінт медично хибний або скеровує неправильно | Перевірити медичну коректність, переписати із правильною логікою |
| **category_dump** | Хінт називає категорію відповіді напряму | Замість названого класу — описати его ознаку / функцію |
| **rewrites_stem** | Хінт просто переказує умову іншими словами | Додати **конкретну рамку мислення** — класифікацію, шкалу, модель, диференціал |
| **too_generic** | Шаблон, що підходить до будь-якого питання теми | Зробити хінт специфічним до конкретної ситуації питання |
| **too_long** | Занадто численні речення / води | Скоротити до 1–2 речень без вступів і повторень |
| **missing** | Поле порожнє | Написати з нуля, дотримуючись стилю |

## Що таке хороший хінт

Хінт — це **інструмент мислення на 1 рівень абстрактніший за відповідь**. Він повинен:

1. **Назвати рамку** — класифікація, шкала, модель, етап, диференціал, принцип.
   - Приклад: «модель кардіореабілітації за ВООЗ», «диференціал верхній vs нижній мотонейрон», «шкала Ашворта»

2. **АБО поставити питання** — одне наштовхуюче питання з чітким маркером уваги.
   - Приклад: «на якому рівні дуги кора → мотонейрон → м'яз?»
   - Приклад: «акцент умови — професія; як це впливає?»

3. **АБО вказати маркер** — на яку ознаку в умові зупинити увагу.
   - Приклад: «зверни увагу на вік дитини», «в умові — фаза захворювання»

## Чого УНИКАТИ

- ❌ Синоніми, переклади, корені слів правильної відповіді
- ❌ Перелік варіантів (А або Б або В)
- ❌ Переписування умови без додавання рамки
- ❌ Фрази типу «Чому це правильно», «Правильна відповідь», «Чому інші неправильні»
- ❌ Шаблонні фрази на кшталт «Зістав ознаки з етапом»
- ❌ Більше ніж 2 речення, вступи, емодзі, маркери списку

## Зразки (еталонні переписи для поширених помилок)

### Проблема: gives_away
```
❌ Поточний: "Гіпорефлексія + атрофія вказують на ураження якого рівня в дузі?"
✅ Кращий: "Гіпорефлексія + атрофія — це маркери ураження якого рівня в системі 'кора → мотонейрон → м'яз'?"
```

### Проблема: category_dump
```
❌ Поточний: "Спастичність 3–4 — це виражений гіпертонус; м'які техніки модулюють, а не блокують іннервацію м'яза."
✅ Кращий: "Ашфорт 3–4 — виражений фокальний гіпертонус; згадай, який клас втручань спрямований на блок нервово-м'язової передачі в окремому м'язі."
```

### Проблема: too_generic
```
❌ Поточний: "Обирай втручання, яке прямо відповідає основній проблемі пацієнта."
✅ Кращий: "Постінсультний геміпарез з спастичністю 3–4 — це вже виражена фокальна гіперактивність; згадай клас втручань, орієнтований саме на нервово-м'язову передачу."
```

### Проблема: rewrites_stem
```
❌ Поточний: "Пацієнтка з остеопорозом має ризик падінь через мезедність кісток і слабість м'язів."
✅ Кращий: "Падіння в літніх — це втрата постурального контролю при перенесенні ваги; які дві рухові якості безпосередньо запобігають цьому?"
```

## Формат виходу

Поверни строго один JSON-обʼєкт:

```json
{
  "batch": <copy from input>,
  "count": <copy from input>,
  "rewrites": [
    {
      "source": "<copy from input>",
      "id": <copy from input>,
      "new_hint": "<переписаний хінт, 1–2 речення, без води>"
    },
    ...
  ]
}
```

Правила:
- Включи УСІ питання з батча (нічого не пропускай).
- `new_hint` — тільки текст, 1–2 речення, без маркерів, без емодзі, без вступів.
- Не змінюй жодних інших полів.
- Дотримуйся правил із розділу «Що таке хороший хінт» та уникай помилок із розділу «Чого уникати».
- Якщо хінт уже хороший (щоб кампромісу, все ж можеш спробувати зробити його ще конкретнішим).
